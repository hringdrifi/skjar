# RP2040 ↔ CM0 通信仕様

RP2040 と CM0 の間のやり取りを、ここに1か所だけ定義する。RP2040 のファームウェアと CM0 のソフトウェアは、どちらもこの文書に従う。

| 経路 | 線 | 使い道 |
|---|---|---|
| UART | `RP_TXD` / `CM0_TXD`（CM0 の GPIO15 / 14） | 状態のやり取り、タッチキー、コンソール（1 章） |
| HID over I²C | `KB_SDA` / `KB_SCL` / `KB_INT`（CM0 の GPIO23 / 24 / 25） | 物理キーを CM0 の Linux に渡す（2 章） |

詳しい背景は [design-decisions.md](design-decisions.md) の「3. RP2040 ↔ CM0 の接続」を参照。

---

## 1. UART

**形式は案（2026-11-09）。** CM0 側は [software/ui/](../software/ui/)、RP2040 側は [firmware/rp2040/](../firmware/rp2040/)（`cm0_link.rs`）の試作が使っている。どちらも実機では未確認。

### 決まっているやり取り

| 方向 | 内容 |
|---|---|
| CM0 → RP2040 | タッチキーの入力（RP2040 が HID として PC に送る） |
| CM0 → RP2040 | 「動作中」の定期的な通知（途絶えたときの扱いは未定） |
| RP2040 → CM0 | シャットダウンの要求 |
| RP2040 → CM0 | 1.5 A のときのバックライトの上限値 |
| RP2040 → CM0 | 電源の状態（使用中のポート、電流宣言） |
| CM0 → RP2040 | LCD の電源を切る依頼（長時間の待機時など） |
| CM0 → RP2040 | RP2040 を UF2 の書き込みモードで再起動する要求 |

- 物理キーの入力は UART では送らない（2 章の HID over I²C で送る）。
- CM0 の起動の早い段階のログ（コンソール）も、この UART に出る。やり取りの形式は、ログが混ざっても読み飛ばせるように決める。

### 1.1 線の設定

- 115200 bps、8N1、フロー制御なし。CM0 側は mini UART（`/dev/serial0` → `ttyS0`）。PL011 は Bluetooth が使う。
- CM0 のカーネルのログ（`console=serial0,115200`）は残す。シリアルのログイン（`serial-getty@ttyS0`）は止めて、UART は UI（`skjar-ui`）が開く。
- カーネルのログは UI の書き込みの途中にも割り込みうる。そのため、どちらの向きも、下の形の行だけを読み、それ以外の行と、壊れた行は捨てる。

### 1.2 行の形

```
$SK,<コマンド>[,<引数>...]*<CRC>\n
```

- ASCII の 1 行で 1 メッセージ。`\r` は無視する。1 行は 64 バイトまで。
- 受ける側は、行の中の最後の `$SK,` から読む（ログが改行なしで前に付いても拾えるように）。
- `<CRC>`：`$` の次から `*` の前まで（`SK,` を含む）の CRC-8（多項式 0x07、初期値 0x00、反転なし）を、16 進の大文字 2 桁で書く。
- 数値は、特に書かないかぎり 10 進。HID の使用法のページとコードは 16 進（`0x` を付けない）。
- 知らないコマンドは捨てる（新しいコマンドを足しても、古い相手が止まらないように）。
- 例：`$SK,ALIVE,0*3E`、`$SK,KEY,07,1E,1*9B`（タッチキーの「1」を押した）。CRC の確認値は、`123456789` で 0xF4。

### 1.3 CM0 → RP2040

| コマンド | 引数 | 内容 |
|---|---|---|
| `HELLO` | — | UI が起動した。RP2040 は今の状態（`PWR`、`BLMAX`、`OUT`、`TKL`、`LAYER`）をすべて送り直し、押されたままのタッチキーをすべて離す |
| `ALIVE` | `<seq>`（0〜255、毎回 1 増やす） | 動作中の通知。1 秒ごと。3 秒途絶えたら、RP2040 はタッチキーをすべて離す（ウォッチドッグとしての扱いは未定） |
| `TK` | `<index>,<1 か 0>` | 画面のタッチキー（Keys タブの 2 段 × 12 キー）を押した（1）・離した（0）。`index` は 0〜23（上の段が 0〜11、下の段が 12〜23、どちらも左から）。RP2040 は、キーマップの 7 + index / 6 行目、index % 6 列目のキーとして RMK に渡す（レイヤーと Vial が効く） |
| `KEY` | `<page>,<usage>,<1 か 0>` | 割り当てが固定のキー（Media タブのボタン）を押した（1）・離した（0）。`page` は `07`（キーボード。修飾キーは E0〜E7）か `0C`（Consumer） |
| `PTR` | `<dx>,<dy>,<buttons>` | トラックパッドの動きとボタン。`dx` / `dy` は −127〜127 の相対値（右・下が正）。`buttons` はビット 0 が左、1 が右、2 が中のボタンで、押している間ずっと立てる |
| `WHEEL` | `<v>,<h>` | スクロール（−127〜127）。`v` は正で上へ、`h` は正で右へ（HID のマウスのホイールと AC Pan と同じ向き） |
| `OUT` | `AUTO` / `PC` / `CM0` | 物理キーの出力先を手動で選ぶ。`AUTO` で自動に戻す（2.6） |
| `LCD` | `0` / `1` | LCD の電源を切る・入れる依頼 |
| `UF2` | — | RP2040 を UF2 の書き込みモードで再起動する |

- タッチキーは、物理キーの出力先にかかわらず、いつも UART で RP2040 に送る。RP2040 は、物理キーと同じ出力先（PC の USB HID か、CM0 への HID over I²C）に出す。
- トラックパッド（`PTR`、`WHEEL`）も同じ。RP2040 はマウスのレポートにして、物理キーと同じ出力先に出す。`HELLO` を受けたときと、`ALIVE` が 3 秒途絶えたときは、ボタンをすべて離す。
- 指の動きの判定（1 本指で移動、叩いて左クリック、2 本指でスクロール、2 本指で叩いて右クリックなど）は CM0 の UI がする。RP2040 は届いた値をそのまま出すだけ。

### 1.4 RP2040 → CM0

| コマンド | 引数 | 内容 |
|---|---|---|
| `ALIVE` | `<seq>`（0〜255） | 動作中の通知。1 秒ごと。CM0 は 3 秒途絶えたら、RP2040 とつながっていないものとして、状態の表示を消す |
| `PWR` | `<A か B>,<3A / 1.5A / DEF>` | 使用中のポートと、その電流宣言 |
| `BLMAX` | `<0〜255>` | バックライトの上限（255 で上限なし。1.5 A のとき下げる。2.4） |
| `OUT` | `<PC / CM0 / NONE>,<AUTO / MAN>` | 物理キーの今の出力先と、自動か手動か |
| `LAYER` | `<n>` | RMK の今のレイヤー（有効なレイヤーのうち一番上） |
| `TKL` | `<layer>,<index>,<code>` | タッチキー `index` の、レイヤー `layer` での割り当て。`HELLO` を受けたときに、すべてのレイヤー・すべてのタッチキーの分を送る（Vial でキーマップを変えたあとも送り直す予定）。`code` は下の表 |
| `USER` | `<n>,<1 か 0>` | Vial の USER キー（RMK の `User(n)`）を押した・離した。UI は USER0〜3 で Keys / Pad / Media / System のタブを開く |
| `ACT` | — | 文字や機能のキー（修飾キー、レイヤーキー、USER キー、メディアキー、マウスキー以外）が押された。UI は設定によって元のタブに戻る。続けて押されたぶんは 1 回にまとめる |
| `SHUTDOWN` | — | シャットダウンの要求。CM0 は `poweroff` し、終わると `CM0_HALT`（GPIO26）が High になる |

`TKL` の `code`（キーの動作。UI がキーの表示にする。software/ui/src/keylabel.c）：

| 形 | 内容 |
|---|---|
| `K<hh>` | キー（RMK の `HidKeyCode` の 16 進。0x04〜0xE7 は HID の使用法と同じ、0xA5〜0xBE はシステム・メディア） |
| `K<hh>+<mm>` | 修飾キー付きのキー（`mm` は修飾キーのビット。ビット 0 が LCtrl … 7 が RGui） |
| `C<hhh>` / `S<hh>` | Consumer / System Control |
| `M<mm>` | 修飾キーだけ |
| `L<n>` / `G<n>` / `D<n>` / `O<n>` | レイヤー（押している間 / 切り替え / 既定 / 1 回だけ） |
| `U<n>` | USER キー |
| `<tap>/<hold>` | タップとホールドで違う動作（例：`K2C/L1` はタップでスペース、長押しでレイヤー 1） |
| `-` / `T` / `?` | 何もしない / 透過（下のレイヤーを見る） / 表示できない種類 |

## 2. キー入力（HID over I²C）

RP2040 が I²C の HID デバイス（ターゲット）になり、CM0 の Linux は標準の `i2c-hid` ドライバで普通のキーボードとして扱う。プロトコルは Microsoft の「HID over I2C Protocol Specification」v1.0 に従う。

### 2.1 バス

| 項目 | 内容 |
|---|---|
| CM0 側 | `i2c-gpio`（ソフトウェアの I²C）。SDA = GPIO23、SCL = GPIO24（標準のオーバーレイの初期値）。速度は約 100 kHz |
| RP2040 側 | I2C0 のターゲット。SDA = GPIO24、SCL = GPIO25 |
| 割り込み | `KB_INT`：RP2040 の GPIO13 → CM0 の GPIO25。**Low で通知**（レベル） |
| プルアップ | `KB_SDA` / `KB_SCL` は 4.7 kΩ、`KB_INT` は 10 kΩ。どれも `+3V3_CM0` へ |
| I²C のアドレス | **0x2C**（試作の値）。このバスには RP2040 しかいないので、自由に決めてよい |

- **`i2c-gpio` にする理由：** Raspberry Pi の I²C ハードウェアはクロックストレッチに正しく対応しておらず、ターゲットの RP2040 は読み出しのたびに SCL を引き延ばすため。
- **帯域：** 入力レポート 1 回は 11 バイト程度（長さ 2 ＋ レポート ID 1 ＋ キーボード 8）で、100 kHz で約 1 ms。キー入力には十分。

### 2.2 RP2040 のピンの約束（CM0 に電流を流し込まないため）

CM0 が OFF のときは `+3V3_CM0` が 0 V になり、3 本とも 0 V になる。RP2040 は常に電源が入っているので、次を守る。

- **High を出さない。** I²C はもともとオープンドレイン。`KB_INT` も、出力値を 0 に固定し、出力の有効・無効を切り替えてオープンドレインを真似る（RP2040 には本物のオープンドレインがない）。
- **内部プルアップを使わない。** pico-sdk のサンプルにある `gpio_pull_up()` を真似しない。リセット直後の初期設定のプルダウンも切る。

### 2.3 レジスタ

HID ディスクリプタのレジスタの番地だけを、デバイスツリーの `hid-descr-addr` で Linux に伝える。ほかのレジスタの番地は、HID ディスクリプタの中で RP2040 が決める。CM0 は 2 バイト（リトルエンディアン）の番地を書いてから、続けて読む。

| レジスタ | 内容 |
|---|---|
| HID ディスクリプタ | 30 バイト。各レジスタの番地、レポートディスクリプタの長さ、最大の入力 / 出力の長さ、VID / PID |
| レポートディスクリプタ | HID のレポートの定義（2.4） |
| 入力 | CM0 が番地なしで読むと、先頭 2 バイトの長さに続いて入力レポートが返る |
| 出力 | CM0 から出力レポート（LED の状態）を受け取る |
| コマンド / データ | `RESET`、`SET_POWER`、`GET_REPORT`、`SET_REPORT` |

試作では次の番地にしている（[firmware/rp2040/src/hid_i2c.rs](../firmware/rp2040/src/hid_i2c.rs)）。

| レジスタ | 番地 |
|---|---|
| HID ディスクリプタ | 0x0001 |
| レポートディスクリプタ | 0x0002 |
| 入力 | 0x0003 |
| 出力 | 0x0004 |
| コマンド | 0x0005 |
| データ | 0x0006 |

- 最大の入力の長さは 11 バイト、最大の出力の長さは 4 バイト（長さ 2 ＋ レポート ID 1 ＋ LED 1）。
- VID / PID は、試作では pid.codes のテスト用（0x1209 / 0x0001）。製品の値は未定。

### 2.4 レポート（案）

| レポート ID | 向き | 内容 |
|---|---|---|
| 1 | 入力 | キーボード（修飾キー 1 バイト、予約 1 バイト、キー 6 個） |
| 1 | 出力 | キーボードの LED（Num / Caps / Scroll Lock など）。キーの RGB で表示できる |
| 2 | 入力 | Consumer Control（音量、メディア操作など） |
| 3 | 入力 | マウス（ボタン 5 個、X、Y、ホイール、AC Pan。どれも −127〜127 の相対値）。トラックパッド（1 章の `PTR` / `WHEEL`）と RMK のマウスキー |

### 2.5 動作の流れ

1. **CM0 が OFF のとき**（`CM0_RUN_PG` が Low）：I²C のターゲットを止め、`KB_INT` は離しておく（Low に引かない）。たまったキー入力は捨てる。
2. **CM0 が起動したとき：** Linux が `SET_POWER`（ON）と `RESET` を送る。RP2040 は `RESET` を受けたら `KB_INT` を Low にし、長さ 0 の入力（2 バイトとも 0）を返す。
3. **キーを押したとき：** RP2040 が入力レポートを用意して `KB_INT` を Low にする。CM0 が入力レジスタを読んだら、次のレポートがなければ `KB_INT` を離す。
4. **出力レポート**（Caps Lock などの LED）を受けたら、キーの RGB に反映する。
5. **CM0 が止まったとき**（`CM0_HALT` か `CM0_RUN_PG` の変化）：1 に戻る。

### 2.6 物理キーの出力先

物理キーは、PC（Port A の USB HID）か CM0（この章の HID over I²C）のどちらかに出す。どちらに出していても、UART（1 章）は状態のやり取りとタッチキーに使う。

| 切り替え | 内容 |
|---|---|
| 自動 | RP2040 が USB のマウントの状態（`tud_mounted()` / `tud_suspended()`）を常に見る。PC にマウントされたら PC へ、外れたら（抜いた、USB 電源アダプタだけ、PC がスリープ）CM0 へ出す |
| 手動 | キーの組み合わせかタッチ UI（UART で RP2040 に伝える）で、今の出力先を切り替える。PC につないだまま CM0 を使うときのため。手で切り替えたら、次に Port A が抜き差しされるまで自動の切り替えは止める |
| 表示 | 今の出力先をタッチ画面とキーの RGB で示す |

- **PC がつながっているかの判定：** まず Port A の CC の電圧で、何かが挿さっているかを見る（挿さっていないときは USB を有効にしない）。USB 電源アダプタも CC をプルアップするので、PC かどうかは USB に列挙されたか（マウント）で見分ける。
- **CM0 が OFF のとき**は、手動で CM0 を選んでいても PC に出す（PC がなければどこにも出さない）。
- 手動の切り替えのキーの組み合わせと、自動の切り替えの細かい条件（スリープの扱いなど）は未定。

### 2.7 CM0 側の設定

`i2c-gpio` のバスの下に、`hid-over-i2c` のデバイスを定義するオーバーレイ（[skjar-keyboard-overlay.dts](../software/os/overlays/skjar-keyboard-overlay.dts)）。

```dts
keyboard@2c {
	compatible = "hid-over-i2c";
	reg = <0x2c>;                  /* I²C のアドレス */
	hid-descr-addr = <0x0001>;     /* HID ディスクリプタのレジスタの番地 */
	interrupt-parent = <&gpio>;
	interrupts = <25 8>;           /* GPIO25、IRQ_TYPE_LEVEL_LOW */
};
```
