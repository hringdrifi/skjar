# 設計判断の記録

SKJÁR の設計で決めたことと、その理由をまとめる。最初の版は 2026-10-30。その後の変更の日付と経緯は Git の履歴を参照。

数値の根拠になった一次資料の要点は [references/README.md](references/README.md) にある。

## 1. 全体構成

### 1.1 USB-C は2ポート
| ポート | 通信 | 役割 |
|---|---|---|
| **Port A（KB）** | RP2040 の USB（Full Speed） | PC に HID キーボードとして接続する。給電にも使う |
| **Port B（SYS）** | CM0 の USB（High Speed） | rpiboot での USB 起動と書き込み、開発用（シリアル / Ethernet gadget）。給電にも使う |

- **理由：**
  - CM0 だけで HID を担うと、Linux が起動するまで（数秒〜十数秒）キーが効かない。BIOS や BitLocker の画面で使えず、Linux が止まるとキーボードも止まる。
  - hub IC を使って 1 ポートにまとめる案もあった。しかし、hub 越しの rpiboot の相性問題と、迂回用のスイッチが要ることから、2 ポートに分けた。
- **Port B はデバイス専用。USB 機器をつなぐホスト機能は付けない。** 周辺機器は Wi-Fi / Bluetooth でつなぐ。
  - Port B をホストにも使う案は、やめた。5 V を送り出す向きにすると、TPS2121 が自分の出力を Port B からの給電と見て切り替えてしまう。防ぐには入力を切るスイッチと USB-C の制御 IC が要り、ホストで使う間は Port A からの給電も必須になる。
  - ホスト専用のポートを別に足す案もある。CM0 の USB は 1 系統なので、USB の切り替えスイッチで Port B と分け合う（hub IC にすると rpiboot が使えなくなる）。必要になったら、この方式で足す。
- **1本でも全部動く：** Port A の相手が 1.5 A 以上を宣言すれば、Port A だけで全機能が動く。「ケーブル1本で動く」という目標は維持している。
- **コネクタ：** HRO **TYPE-C-31-M-12**（LCSC C165948、Extended。手持ちあり）。フットプリントは KiCad 標準の `Connector_USB:USB_C_Receptacle_HRO_TYPE-C-31-M-12`。
  - パッド名が回路図のシンボル（`USB_C_Receptacle_USB2.0_16P`）のピン番号とそのまま一致する。
  - C2765186・C393939 も信号パッドの配置は同じで、違いはシールドの固定足の位置（約 0.2 mm）と穴の径（0.6 mm）だけ。HRO 用の穴（0.8 mm）で作っておけば、代わりに載せられる可能性が高い。本体の長さ・高さは品番ごとに確認が必要。

### 1.2 役割の分担
- **RP2040：** キーマトリクスを読み、キーの入力を出す。電源の判断とキーの RGB も RP2040 が行う。
  - **PC へ（Port A の USB HID）：** PC へ出す HID はすべて RP2040 が出す（物理キー、タッチキー、Consumer Control、マウス）。
  - **CM0 へ（HID over I²C）：** 物理キーを、CM0 の Linux に普通のキーボードとして渡す（[3](#3-rp2040--cm0-の接続)）。
  - 物理キーをどちらへ出すかは、ファームウェアで切り替える。USB のマウントの状態を見て自動で切り替え（PC にマウントされたら PC、外れたら CM0）、キーの組み合わせかタッチ UI で手動でも切り替えられるようにする。手動で選べるのは、PC につないだまま CM0 を使う場面があるため。詳しくは [protocol.md](protocol.md) の 2.6。
- **CM0：** Linux とタッチ UI を担当する。タッチキーの入力は UART で RP2040 に送り、RP2040 が PC へ HID として出す。

### 1.3 マイコン
- **RP2040** を基本とする。GPIO が足りなくなったら RP2350B を検討する。

### 1.4 CM0 の型番と記憶媒体
- **CM0100000（Wi-Fi / Bluetooth あり、eMMC なしの CM0Lite）＋ microSD から起動する。**
  - 理由：本体が一番安い。容量をカードで選べる。電源断などで記憶媒体が故障しても、カードの交換で済む（eMMC は直付けなので CM0 ごと交換になる）。
  - Wi-Fi は音楽のストリーミング再生などに使うので、無線ありを選ぶ。
  - サイバーデックでは定番の構成（ClockworkPi uConsole も CM4 Lite ＋ microSD）。
- **microSD のスロットは CM0 の SD 用のピン（122〜132 番）につなぐ。** SD_VREF は `+3V3_CM0`（3.3 V の信号）。
  - SD 用のピンは CM0Lite でしか使えない。eMMC 版の CM0 を載せた場合、スロットは使われず eMMC から起動する。基板はどちらにも対応する。
  - 速度は eMMC とほぼ同じ（どちらも SoC の同じ SD コントローラにつながり、20〜25 MB/s 程度）。
  - 容量は SDXC の 2 TB まで（SDUC は不可）。A1 / A2 表示の、品質の良いカードを使う。
- **rpiboot の要求は残す。** nRPI_BOOT を Low にすると、SD カードではなく Port B の USB から起動する。起動しなくなったときの救済に使う。要求は RP2040 がキーの組み合わせで受ける（専用のスイッチは廃止。[2.4](#24-電流宣言ごとの動作)）。SD カードを USB ストレージとしてパソコンに見せられるか（カードを抜かずに書き換えられるか）は、試作で確認する。
- **電源断への強さ：** eMMC も SD カードも、書き込み中の電源断でファイルシステムが壊れることはある。媒体に頼らず、読み取り専用のルートファイルシステム（[1.5](#15-いきなりの電源断への備え)）と、RP2040 が CM0 のシャットダウンを待ってから電源を切る手順で守る。

### 1.5 いきなりの電源断への備え
- **前提：** キーボードとして使っているとき（Linux を使っていないとき）は、CM0 が動いていても、ケーブルはそのまま抜かれるものと考える。Port A だけで給電していると、抜いた瞬間に CM0 の電源が落ちる。電池はなく、TPS2121 の出力側のコンデンサ（470 µF）は切り替えの一瞬を持たせるだけで、シャットダウンまでは持たない。
- **コアの領域は書き込み不可にする：** ルート（OS とアプリ）は読み取り専用でマウントする。一時ファイルやログは overlayfs か tmpfs に置き、メモリ上で捨てる。Raspberry Pi OS の Overlay File System の機能（`raspi-config`）を使い、素の OS の方針から外れないようにする。
- **書き込みが要るものは別のパーティションに置く：** 設定、キーマップ、ユーザーのファイルなど。普段は読み取り専用でマウントし、保存するときだけ書き込みにして、終わったらすぐ読み取り専用に戻す。
  - 書き込みは、一時ファイルに書いて `fsync` してから名前を変える。途中で切れても、古いか新しいかのどちらかが残る。
- **書き込み中は画面に出す：** データの領域が書き込みになっている間は、タッチ画面（とキーの RGB）で「今は抜かないで」と示す。表示が出ていなければいつ抜いてもよい、という約束にする。
- **OS の更新など長い書き込み：** Port B に電源がつながっているときだけ行う（いきなり抜かれても電源が切れない）。
- **やめた案：** スーパーキャパシタなどでシャットダウンまで電源を持たせる案。CM0 と LCD で 1 A 前後を数秒持たせる必要があり、部品が大きく回路も増える。

## 2. 電源

### 2.1 基本方針
- **USB PD には対応しない。** 5 V 専用で、上限は 15 W（5 V / 3 A）。
- **昇降圧の電源 IC は入れない。** USB の VBUS をそのまま使い、電圧降下が小さくなるシンプルな構成にする。CM0 と LCD の「4.75 V 以上」という仕様は、安全側の値とみなす。

### 2.2 電源切り替え IC：TPS2121RUXR（LCSC C485916）
- **候補を比べた結果：** TPS2117 は耐圧が 5.5 V、TPS2116 は 2.5 A、TPS2120 は BGA しかなく、LM66200 は優先ポートを指定できない。
- **IN1 に Port B、IN2 に Port A** をつなぐ。
- **高速切り替えモード（XCOMP）で使う。**
  - PR1 に Port B の電圧を、CP2 に Port A の電圧を、それぞれ分圧して入れる。PR1 側の分圧比を少し大きくする（例：B 側 0.34、A 側 0.30）。
  - 両方つないでいる間は B を使い、B の電圧が約 4.4 V を下回ったら 5 µs で A に切り替わる。
  - PR1 だけを使う方式（VREF モード）だと、切り替えに 100 µs かかる。1.4 A、470 µF の条件で約 0.3 V 下がるので不採用にした。
- **B を優先する設定は、ハードウェアで固定する。** マイコンから強制的に切り替える経路は付けない（TPS2121 には SEL ピンもない）。
- **電流制限（ILM）：** 30 kΩ（C22984、Basic）で約 2.46 A。計算式は R [kΩ] = 65.2 / I^0.861。当初は 29.4 kΩ（約 2.52 A）だったが、0603 の 29.4 kΩ は Extended で在庫も少ない（513 個）ため、Basic の 30 kΩ にした。
- **ソフトスタート（SS）：** 100 nF で約 780 V/s。
- **状態出力（ST）：** RP2040 の 3.3V にプルアップする。High なら B から、Low なら A から給電している。
- **出力側のコンデンサ：** 470〜1000 µF の低 ESR コンデンサを置く（容量は試作で調整）。スーパーキャパシタは載せない。
- **過電圧保護（OV1 / OV2）を使う：** 各ポートの VBUS を 100 kΩ / 22 kΩ で分圧し、約 5.9 V（誤差込みで 5.59〜6.17 V）で遮断する。故障した充電器から CM0 と LCD を守るため。電圧降下は増えない。
- **USB の ESD 対策（USBLC6-2SC6）の VBUS ピンは `+5V` につなぐ：** USBLC6 は VBUS と GND の間にも TVS を内蔵しているので、各ポートの VBUS に直接つなぐと、故障した充電器の過電圧で先に壊れるおそれがある。過電圧保護の後ろの `+5V` につなぐ。
- **VBUS の TVS ダイオードは付けない：** 抜き差しの瞬間の跳ね上がりは、TPS2121 が入力の安定を待ってから出力を出すので、`+5V` に届かない。TPS2121 の入力は 22 V まで耐える。

### 2.3 CC の判定
- 両ポートの CC1 / CC2 に、個別部品の 5.1 kΩ（Rd）を付ける。
- **RP2040 の ADC（4本）で読んで判定する。** 判定の電圧範囲は、Default が 0.25〜0.61 V、1.5 A が 0.70〜1.16 V、3 A が 1.31〜2.04 V。
- TUSB320 は使わず、空きパターンも作らない。
- Port A に PC がつながっているかの検出にも、CC の電圧を使う。RP2040 は自分の電源で動いている（セルフパワーの）デバイスなので、PC がつながっていないときに D+ をプルアップしてはいけないため。

### 2.4 電流宣言ごとの動作
| 使用中のポートの電流宣言 | CM0 | LCD | バックライト | キーの RGB |
|---|---|---|---|---|
| 3 A | ON | ON | 上限なし | 上限あり |
| 1.5 A | ON | ON | 上限あり（値は実測後に決める） | 低い上限 |
| Default | OFF | OFF | — | 低い上限か消灯 |

- **キーの RGB の上限：** 全点灯（白・最大）で約 1.5 A になるので、どの電流宣言でもファームウェアで明るさの上限をかける。値は実測後に決める（[6.1](#61-キーの-rgb-バックライト)）。

- **Default で Port A を使っている場合：** HID キーボードとしてだけ動く。
- **例外（rpiboot）：** USB ブートの要求があれば、Default でも CM0 だけ ON にする（LCD は OFF）。
  - 要求は**キーの組み合わせ**で出す（電源を入れるときに決めたキーを押しておく、など。詳細はファームウェアで決める）。RP2040 は GPIO23 `BOOT_EN` で N-MOSFET（2N7002）を ON にして nRPI_BOOT を Low に引き、それから GLOBAL_EN を解除する。
  - 以前は専用のタクトスイッチ（SW102、GPIO20 `BOOT_SW`）を付けていたが、廃止して GPIO20 をキーの RGB に回した。スイッチも RP2040 のファームが読んでいたので、キーの組み合わせにしても頼れる度合いは変わらない。
  - CM0 のピンを Low に引くだけなので、CM0 が OFF のときに逆電圧をかけない。RP2040 からのコマンドでも USB ブートに入れられる。
- **給電元が弱い方へ切り替わったとき**（B を抜かれ、A が Default だった場合など）
  1. RP2040 が ST の変化を割り込みで検知する。
  2. LCD の負荷スイッチを即座に OFF にする。
  3. UART で CM0 にシャットダウンを指示する。
  4. CM0 から完了の通知を受けたら（またはタイムアウトしたら）、GLOBAL_EN を Low にする。

### 2.5 CM0 と LCD の電源制御
| 対象 | 担当 | 方法 |
|---|---|---|
| CM0 の電源 | RP2040 | **GLOBAL_EN** を N-MOSFET で Low に引く（GLOBAL_EN は CM0 の内部で 5 V にプルアップされているため、直接つながない）。MOSFET のゲートをプルアップしておき、初期状態は OFF。CM0 用の負荷スイッチは使わない（電圧降下の面でも有利） |
| LCD の電源 | RP2040 | 負荷スイッチ **TPS22965DSGR**（C122837、16 mΩ。OFF 時に出力を放電する機能付き）。EN はプルダウンして、初期状態は OFF |
| バックライトの明るさ | CM0 | パネルの I²C（sysfs で 0〜255）。1.5 A のときの上限値は、RP2040 から UART で受け取る |

- **電源の順序**（CM0 に逆電圧をかけないため）
  - 入れるとき：CM0 が起動して RUN_PG が High になってから、LCD を ON にする。
  - 切るとき：先に LCD を OFF にしてから、GLOBAL_EN を Low にする。
- **CM0 の復旧：** GLOBAL_EN で電源を入れ直す方式に一本化する。リセット線は付けない（RUN_PG にはテストパッドだけ付ける）。CM0 から UART で定期的に届く「動作中」の信号が途絶えたときの扱い（ウォッチドッグ）は、ソフトウェアで決める。

### 2.6 電圧降下の対策
- USB-C コネクタの VBUS / GND 端子は、すべてつなぐ。
- 5 V は広い銅箔（ベタ）で引き、コネクタから負荷までを短くする。
- CM0 の 5V ピン（67, 68）と LCD の入力端子に、測定用のテストパッドを付ける。

## 3. RP2040 ↔ CM0 の接続

CM0 の電源が切れているときは、どのピンにも外部から電圧をかけてはいけない（CM0 データシート 4.2.1）。RP2040 は常に電源が入っているので、すべての信号で対策を決めた。

| 信号 | 方向 | 対策 |
|---|---|---|
| UART（RP2040 TX → CM0 GPIO15） | RP2040 → CM0 | バッファ **SN74LVC1G125DBVR**（C23654）を入れ、CM0 の 3.3V で動かす（電源が落ちると出力が切り離される） |
| UART（CM0 GPIO14 → RP2040 RX） | CM0 → RP2040 | RP2040 側のプルアップを無効にする |
| GLOBAL_EN | RP2040 → CM0 | N-MOSFET で Low に引くだけ |
| RUN_PG（電源正常の通知） | CM0 → RP2040 | RP2040 側はプルなし |
| シャットダウン完了の通知 | CM0 → RP2040 | CM0 の GPIO（`gpio-poweroff`）。RP2040 側はプルなし |
| シャットダウンの要求 | RP2040 → CM0 | UART のコマンドで送る（ピンを増やさない） |
| キー入力（HID over I²C） | RP2040 → CM0 | プルアップはすべて `+3V3_CM0` 側。RP2040 はオープンドレインで Low に引くだけで、内部プルアップを使わない |

- **方針：なるべく素の Raspberry Pi OS で、大体の機能が動くようにする。** カーネルとドライバは標準のまま、オーバーレイと `config.txt` の設定だけで済ませる。
- **CM0 へのキー入力は HID over I²C にする。** RP2040 が I²C の HID デバイスとして振る舞い、Linux 標準の `i2c-hid` ドライバで普通のキーボードとして使う（Raspberry Pi のカーネルは `CONFIG_I2C_HID_OF=m`）。起動の早い段階（緊急モードなど）から使え、Caps Lock の LED なども OS から標準で返ってくる。
  - **バス：** CM0 の GPIO23（SDA）/ GPIO24（SCL）を **`i2c-gpio`**（ソフトウェアの I²C）で使う。標準のオーバーレイの初期値なので、`dtoverlay=i2c-gpio` だけで済む。Raspberry Pi の I²C ハードウェアはクロックストレッチに正しく対応しておらず、I²C のターゲットになった RP2040 は読み出しのたびに SCL を引き延ばすため。速度は約 100 kHz で、キー入力（1 回 約 15 バイト）には十分。
  - **割り込み `KB_INT`：** RP2040 の GPIO13 が Low に引き、CM0 の GPIO25 で受ける。
  - **プルアップ：** `KB_SDA` / `KB_SCL` は 4.7 kΩ、`KB_INT` は 10 kΩ で、どれも `+3V3_CM0` へ（cm0 シート）。CM0 が OFF のときは線が 0 V になり、CM0 に電圧がかからない。
  - **UART は状態のやり取りとコンソールに残す。** 起動の早い段階のログは UART にしか出ないため。キー入力を UART から外したので、UART の帯域はこれらに使える（両立のさせ方は [protocol.md](protocol.md)）。
  - **UART でキー入力を送る案は採らない。** Linux 側に自作のデーモン（`uinput`）が要るうえ、CM0 で自由に使える UART は 1 本だけ（もう 1 本は Bluetooth）で、コンソールと両立しない。カーネルのシリアルキーボード（`CONFIG_SERIO_SERPORT`）も Raspberry Pi のカーネルには入っていない。
  - **RP2040 のファームウェア：** I²C ターゲットのドライバと HID over I²C の処理は自作する。QMK はどちらにも対応していない（QMK を使うなら、出力先を USB と切り替える仕組みに組み込む）。
  - **やり取りの仕様**（I²C のアドレス、レジスタ、レポート、CM0 が OFF のときの扱い）は [protocol.md](protocol.md) の「2. キー入力（HID over I²C）」に書く。

- **RP2040 のファーム更新：** Port A から UF2 で書き込む。CM0 からの SWD はやめる（RP2040 の SWDIO は内部でプルアップされていて、CM0 に電圧がかかるため）。SWD はテストパッドだけ用意する。
- **CM0 のデバッグ用コンソール：** 外に出ている UART は GPIO14/15 の1組だけで、RP2040 との通信に使う。必要になったら、RP2040 のファームに透過的な中継機能を足す。GPIO14/15 にはテストパッドを付ける。
- **テストパッドは惜しまず付ける。**

## 4. ディスプレイ

- **サイズ：** 8.8″（480×1920）。40% 配列の幅（約 230〜245 mm）とガラス外形（240.5 mm）がほぼ一致する。
- **対応機種：** Waveshare の **8.8inch DSI LCD** と **8.8-DSI-TOUCH-A** の両方に対応させる。ガラス・解像度・表示領域は同じで、コネクタと背面の作りだけが違う。
- **DSI：** 22ピン（0.5 mm ピッチ、Raspberry Pi 5 と同じピン配置）の FPC コネクタを1つ付け、4レーン分を配線する。
  - TOUCH-A は、付属の 22ピン FFC で直結する。
  - 8.8inch DSI LCD は、付属の DSI-Cable-12cm（15 → 22ピン）でつなぐ。
  - 15ピンと 22ピンのコネクタを両方載せない理由：DSI の高速信号に枝分かれ（スタブ）ができるため。
- **LCD の電源：** ライトアングルの 2.54 mm 1×3 ピンヘッダ（5V / 5V / GND。Raspberry Pi の 2・4・6番ピンと同じ並び）。
  - TOUCH-A は、付属の「MX1.25 2ピン → 2.54 3ピン」ケーブルをそのまま挿す。
  - 8.8inch DSI LCD は、付属の PH2.0 4ピンケーブル（5V / GND / SDA / SCL）のうち、5V と GND を挿す。SDA と SCL は絶縁して使わない（I²C は FPC 側を使う）。
  - 逆挿しを防ぐため、シルクで「5V 5V GND」と1番ピンの印を入れる。
- **Linux の設定：** config.txt の `dtoverlay` の行で切り替える（`vc4-kms-dsi-waveshare-panel,8_8_inch` か `vc4-kms-dsi-waveshare-panel-v2,8_8_inch_a`）。

## 5. 周辺機能

### 5.1 RTC
- **IC：** **PCF8563T**（NXP、SO-8、C7440、JLCPCB の Preferred Extended）を CM0 の I²C1（GPIO2/3）につなぐ。消費は 250 nA。Linux では `rtc-pcf8563` ドライバで動く。KiCad の標準シンボル `Timer_RTC:PCF8563T` を使う。
  - **水晶：** JGHC S3132768092070 32.768 kHz（C479190、Extended。手持ちの在庫を使う。負荷容量 9 pF、ESR 70 kΩ、±20 ppm、3.2 × 1.5 × 0.75 mm）。RTC のすぐ横に、短い配線で置く。
  - **当初は Epson FC-135（Q13FC13500004、C32346、Basic、負荷容量 12.5 pF）だった。** PCF8563 のデータシートの特性は負荷容量 8 pF の水晶が前提なので、9 pF のほうが時計の進みが小さい。外形もフットプリント（`Crystal_SMD_3215-2Pin_3.2x1.5mm`）も同じ。
  - **当初の案は RV-8263-C7（水晶内蔵）だった。** Basic / Preferred を優先する方針と、手はんだのしやすさ（3.2 × 1.5 mm の 8 ピンは小さすぎる）から、PCF8563T に替えた。
  - **I²C の電圧：** PCF8563 の SDA / SCL は、VDD に関係なく 6.5 V まで受け付ける（絶対最大定格）。ダイオードで VDD が約 3.0 V に下がっても、3.3 V にプルアップされた I²C をそのまま使える。
  - **CLKOUT：** オープンドレインで、電源投入時は出力が有効になっている。プルアップしなければ電流は流れないので未接続にし、ソフトウェアで止める。
- **予備電源：** CR2032（コンビニで買える）。ホルダーは板金のスライド差し込み式の **MY-2032-08**（C964831）。左右反転品の -08-R（C964832）もあり、向きは配置のときに決める。
- **電源の切り替え：** BAT54C（ショットキーダイオード）で、常時 ON の 3.3V と電池のうち高い方から給電する。一次電池に充電しない構成にするため、充電機能付きの RTC（RX8130CE、PCF85263A）は使わない。
  - Basic の 1N4148WS ×2 に替える案もあったが、電圧の落ちが大きい（0.6〜0.7 V）ので採用しない。Basic のショットキー（B5819W など）は、逆向きの漏れ電流で電池を消耗させるおそれがあるので使わない。
- **時刻合わせ：** ネットワーク（NTP）か手動で行う。RP2040 は関与しない。

### 5.2 音声
- **音声 IC：** **TLV320DAC3100**（TI、C179677）。ステレオの DAC に、ステレオのイヤホン出力とモノラルの D 級スピーカーアンプが入っている。I²S（GPIO18/19/21）で音を、I²C（`I2C1`、アドレス 0x18。RTC と相乗り）で設定を受け取る。
  - **理由：** 内蔵スピーカーに加えて、ステレオのイヤホンで音楽を聴きたい（Wi-Fi でのストリーミング再生）。当初の MAX98357A はスピーカー専用（BTL 出力）で、イヤホンをつなげない。Raspberry Pi でよく使われる WM8960 は JLCPCB の在庫がなかった。
  - **性能（データシート）：** イヤホン出力は SNR 95 dB、THD+N −82 dB、32 Ω で 20 mW / 16 Ω で 60 mW。スピーカーは 4〜8 Ω。
  - **クロック：** 12 MHz の発振器（Y402）を MCLK に入れ、コーデックを I²S のクロックを出す側（マスター）にする。CM0 はクロックを受ける側（`i2s_clk_consumer`）。
    - **理由：** 標準の `simple-audio-card` だけで動かすため（素の Raspberry Pi OS で動かす方針、3 章）。`simple-audio-card` は `set_sysclk()` を常に MCLK（clk_id 0）で呼ぶので、MCLK を使う構成ならドライバをそのまま使える。ドライバの分周表には MCLK 12 MHz で 44.1 / 48 kHz を作る設定があり、コーデックがマスターになる設定にも対応している（rpi-6.12.y の `tlv320aic31xx.c` で確認）。
    - **当初は MCLK を GND にし、BCLK から PLL で作る構成だった。** BCLK を PLL の入力に選ぶには、マシンドライバを自作するか、ドライバにパッチを当てる必要があった。
    - CM0 の GPCLK から MCLK を出す案は採らない。音声用の周波数を割り切れず、分数分周のジッタが出るうえ、BCLK とも同期しないため。
  - **電源：** SPKVDD は `+5V`。AVDD / HPVDD は `+3V3_CM0` からフェライトビーズ（C1017）を通した `AVDD_CODEC`。DVDD は `+1V8_CM0`、IOVDD は `+3V3_CM0`。どれも CM0 と一緒に ON / OFF し、データシートの推奨する順序（SPKVDD が先）にも合う。
  - **イヤホン出力：** 220 µF の電解コンデンサ（C970695）で直流を切る（16 Ω で約 45 Hz まで）。ジャック側に 10 kΩ の放電抵抗を付けて、抜き差しのポップ音を抑える。
  - **イヤホンジャック：** 3.5 mm の 4 極（PJ-320D-4A、C95562）。2 本目のリング（R2）を GND、スリーブ（S）を検出用にする。3 極のプラグを挿すとスリーブが R2 と S をつなぎ、`HP_DET` が Low になる（100 kΩ で `+3V3_CM0` にプルアップ）。CTIA 配列のマイク付きイヤホンでも音は出る。
  - **制御：** CM0 の GPIO22 が `CODEC_RST`（100 kΩ でプルダウンし、ドライバが離すまでリセットしておく）、GPIO17 が `HP_DET`。
  - **Linux：** カーネルの `tlv320aic31xx` ドライバが TLV320DAC3100 に対応している。デバイスツリーのオーバーレイは自分で書く。イヤホンの検出は GPIO でのジャック検出（`simple-audio-card` の `hp-det-gpio` など）を使い、挿したらスピーカーを止める。
- **スピーカー：** コネクタで後付けにする。使うかどうかはケース設計で決める。
- **ON/OFF ピン（SD）：** プルダウンしておき、CM0 が OFF のときはアンプも止まるようにする。

### 5.3 付けないもの
- ロータリーエンコーダ
- 照度センサー（輝度スライダー、時刻での減光、無操作時の減光で代える。必要になったら CM0 の I²C に後付けできる）
- インジケータの LED（キーの RGB で代える。[6.1](#61-キーの-rgb-バックライト)）

### 5.4 アンテナ
- **技適：** CM0 は技適を取得している（工事設計認証 020-260249、2.4 GHz 帯のみ）。認証の対象アンテナは次の3種。
  - ED-ANT-C（EDATEC の FPC アンテナ。ケーブルは 60 mm）
  - CardputerZero の内蔵品
  - YH2400-5800-SMA-108（Raspberry Pi のロッドアンテナ）
- **本命：** ED-ANT-C。入手先は確認中。

## 6. キーボード
- **配列：** 40%。
- **キースイッチ：** ロープロファイルの **Kailh Choc V2 系**（Choc V2 の各色、Lofree Wizard など）。ホットスワップにする。
  - Choc V2 系なら、どのスイッチでも同じフットプリントで使える。MX と同じ十字の軸なので、MX 用のロープロファイルのキーキャップが使える。
  - 候補から外したもの：Choc V1（キーキャップが Choc 専用品に限られるため）、Gateron Low Profile（フットプリントとソケットが Choc と別物で、両対応の既製品もないため）、Cherry MX Low Profile と超薄型（ULP、X-switch など。入手性とソケットの問題）。
- **キー配列：** 42 キー（[hardware/layout/skjar_kle.json](../hardware/layout/skjar_kle.json)）。右下の `/` は長押しで Shift、2 つのスペースは長押しでレイヤー 1 / 2。
- **キーマトリクス：** **7 行 × 6 列（13 本）**。同じ配列で実績のある組み方。見た目の配列と電気的な配線の対応は、ファームウェアの設定で吸収する。

### 6.1 キーの RGB バックライト
- **キーごとに 1 個：** **SK6812MINI-E**（C5149201）を 42 個。裏面に置き、基板の穴を通してスイッチの LED 窓から光らせる（部品はすべて裏面に置く方針と合う）。数珠つなぎで、データ線は 1 本。QMK の RGB Matrix で使う。
- **位置と穴：** LED の中心は、上から見てスイッチの中心から **4.93 mm 上**（ピンと反対側）。フットプリントは KiCad 標準の `LED_SK6812MINI-E_3.2x2.8mm_P1.5mm_ReverseMount` を使う。これには 3.4 × 3.0 mm の穴（Edge.Cuts）が入っている。
  - 中心の穴（Choc V2 用の 5 mm）との間に残る基板は約 0.93 mm。V2 のガイドピンの穴（中心から −5, −5.15）とは、LED のパッドまで約 0.85 mm 空く。
- **データ線：** RP2040 の GPIO14（`RGB_DATA`、PIO で出す）。SK6812 を 5 V で動かすと High の閾値が 0.7 × VDD ＝ 3.5 V で、3.3 V では足りないので、**SN74AHCT1G125**（C7484、TTL 入力で 5 V 出力）を通す。
- **電源の遮断：** 消灯していても 1 個あたり約 1 mA（42 個で約 40 mA）流れるので、`+5V` から P-MOSFET **AO3401A**（C15127）で切る。ゲートは 2N7002 で引く（RP2040 の 3.3 V では 5 V の P-MOSFET を切れないため）。制御は GPIO20（`RGB_EN`、High で ON）。プルダウンして初期状態は OFF。
  - ゲートにコンデンサを付けて、ゆっくり ON にする（LED の各コンデンサへの突入電流で `+5V` を落とさないため）。
  - SN74AHCT1G125 は LED 側の電源（`+5V_LED`）で動かす。LED の電源を切ったときに、止まっている LED にデータ線から電流を流し込まないため。SN74AHCT1G125 の入力は電源が 0 V でも 5.5 V まで耐える。
- **電流：** 全点灯（白・最大）で約 1.5 A。電流宣言ごとに、ファームウェアで明るさの上限をかける（[2.4](#24-電流宣言ごとの動作)）。
- **GPIO：** RP2040 の GPIO は 30 本すべて使う。GPIO20 は、CM0 の USB ブート要求のタクトスイッチ（SW102）を廃止して空けた。
- **採用しなかった案**
  - LED の電源を `LCD_EN` と共用する：GPIO は増えないが、LCD を消して Port A で PC 用のキーボードとして使うときに RGB が使えない。
  - アンダーグロー（基板の縁に数個）：電流は小さいが、キーごとの表示（レイヤーやインジケータ）ができない。

## 7. 基板と機構
- **構成：** まず「2層・1枚」で成立するかを検討し、駄目なら2枚構成（4層の制御基板＋2層のキー基板）にする。
  - 2層・1枚を採用する基準：
    - JLCPCB の積層（0.8〜1.0 mm）で、90 Ω / 100 Ω の差動線を現実的な線幅で作れる。
    - USB（Port B → CM0）を 2〜3 cm 以内、DSI（CM0 → FPC）を 3〜5 cm 以内にできる。
    - その範囲の GND を途切れさせずに取れる。
- **部品の面：** 部品はすべて裏面に実装する。上面はキースイッチとディスプレイだけにする。
  - ディスプレイの下の上面は、一面 GND にする（裏面の高速信号の基準面にする）。
- **ケーブルの通し方：** ディスプレイの FFC と電源ケーブルは、基板に開けた穴を通して裏面のコネクタにつなぐ。
  - FFC 用の長穴：幅 18〜20 mm × 1.5〜2 mm 程度。電源用の穴：3ピンのハウジングが通る大きさ（約 9 × 4 mm）。穴の縁は角を丸くする。
  - FPC コネクタとピンヘッダは、差し込み口を穴の方に向けて配置する。
- **タイピングアングル：** 角度を付け、深さの取れる奥側（ディスプレイの下）に背の高い部品を集める。手前側（キーの下）は低い部品だけにする。
- **CM0 の取り付け：** 手はんだ（側面端子 132 本、1 mm ピッチ）。推奨フットプリントは、パッド 0.6 × 2.4 mm。
- **実装は自前（リフローと手はんだ）を検討中。** 一番の難所は TPS2121RUXR（HotRod の VQFN、2.0 × 3.0 mm で、はんだの付き具合が外から見えない）。ステンシルの開口は TI の推奨どおりにし、予備の部品も用意する。基板の幅（約 240 mm）が手持ちのリフローの道具に入るかは要確認。
- **抵抗・コンデンサは 0603 に統一する。** 場所に余裕があり、試作で定数を変える部品（水晶の負荷コンデンサ、分圧抵抗など）を付け替えやすい。

## 8. 部品を選ぶ基準
機能を満たすこと、JLCPCB で手に入ること、在庫数、価格。

- **JLCPCB の Basic 部品を優先する。** 次に Preferred Extended（追加料金なし）、最後に Extended（発注ごと・部品の種類ごとに追加料金がかかる）。
- 必要なら、Basic にするために部品を選び直す。ただし、機能や電池の持ちなど、設計の要件を落としてまでは替えない。
- **手持ちの在庫がある部品は、それを優先してよい**（自前で実装するため、Extended の追加料金は関係しない）。例：3.3 V の LDO は AP2127N-3.3（C176954）。
- **抵抗・コンデンサ（0603）：**

| 値 | LCSC | 区分 |
|---|---|---|
| 27 Ω 1% | C25190 | Preferred |
| 1 kΩ | C21190 | Basic |
| 5.1 kΩ 1% | C23186 | Basic |
| 10 kΩ | C25804 | Basic |
| 22 kΩ | C31850 | Basic |
| 30 kΩ 1% | C22984 | Basic |
| 43 kΩ | C23172 | Preferred |
| 51 kΩ | C23196 | Basic |
| 100 kΩ | C25803 | Basic |
| 220 kΩ | C22961 | Basic |
| 27 pF C0G | C107045 | Preferred |
| 1 nF | C1588 | Basic |
| 100 nF 50 V | C14663 | Basic |
| 1 µF 50 V | C15849 | Basic |
| 10 µF 25 V | C96446 | Basic |

  Preferred は JLCPCB のページでは Extended と表示されることがある。発注時に区分を確かめる。10 µF は +5V 側で使うので、電圧による容量の低下が小さい 25 V 品にした。
